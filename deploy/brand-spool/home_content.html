真正的清单是 GET /v1/models 的返回，范围是你这把 key 所属分组能用的模型，不是整池。model id 照返回原样填，不要凭记忆手写。看不到的模型，就是不在你分组的白名单里。

报错怎么读

先看 body 里的 code，别只看状态码 04 · FAULT CODES
HTTPBODY CODESTATEACTION
429 QUOTA_EXHAUSTEDUSAGE_LIMIT_EXCEEDEDinsufficient_quota（Codex 路径） HALT 额度用完。重试无用，找管理员加额。
429 USER_RPM_EXCEEDEDGROUP_RPM_EXCEEDED BACKOFF 限速打满。退避几秒重试。
403 INSUFFICIENT_BALANCE HALT 余额不足。找管理员。
503 无 code BACKOFF 池里暂时没有能跑这个模型的账号。退避重试；一直 503 就去群里说。
404 not available for this group CONFIG 模型不在你分组的白名单里。换分组，或找管理员加。

额度用完不降级、不静默截断——你会看到报错，不会看到胡话。401 只有一个意思：key 不对。

key 丢了不用重建：在 /keys 列表里随时可以整条复制回来，不是只显示一次。用量在控制台看得到；不想登录，去 /key-usage 输 key 查自己那一份。

规矩

三条，没有例外 05 · RULES

key 不进仓库、不贴群。

泄漏时只吊销那一路，所以按用途分开开几把；能登录你账号的人就能拿走你所有的 key。

跑批量前群里说一声。

错开高峰；CI 单独开一把 key，别用交互那把。

额度按人分配，要超提前找管理员。

不要换别人的 key 顶，用量会记在他头上。

SPOOL = Simultaneous Peripheral Operations On-Line，IBM 1959 年给打印队列起的名字：一台昂贵的共享设备，很多人往里发作业，用量记在各人名下。名字只借典故：spool 不攒批，请求实时转发。
