你不拥有那台打印机，你只是往里发作业。

spool 是我们内部的 AI 网关。公司买的上游订阅账号在这边排成一个池，对外只露一个兼容端点。你拿一把自己的 key，改两个环境变量，用量记在你名下。就这些。

base URL

https://spool.corp.internal

这一页不跑 JavaScript，所以没有复制按钮。点一下带琥珀竖条的块里的命令行，那一行整行选中，Cmd-C 拿走；灰色的注释行不选中，本来也不用复制。
[base URL：以控制台 API Keys 页面显示的为准；本页可见 3 处 https://spool.corp.internal，换的时候一起换，然后删掉这句]

这是什么

一台机器，站在你和上游之间。公司买的 Claude / GPT-Codex / Gemini / Antigravity 订阅账号都挂在 spool 后面，按类别组成几个池。这次请求走的是哪个账号，你不需要知道，那是调度的事。

你拿到的是一个 OpenAI / Anthropic 兼容的 base URL，和一把只属于你的 key。认这两套协议的客户端都能直接接上：Claude Code、Codex、Cursor、各语言的 SDK。

为什么不是每人开一个账号：账号贵、配额零散、人走了要回收、出了事说不清是谁在用。排成池以后，这四件事各自有了答案。

spool 不对外、不卖钱、没有套餐页。它跑在自建的 Sub2API 上，代码没改，改的只是名字和这块首页。

SPOOL = Simultaneous Peripheral Operations On-Line，IBM 1959 年给打印队列起的名字：一台昂贵的共享设备，很多人往里发作业，用量记在各人名下。六十年后是同一个问题。名字只借典故：spool 不攒批、不排队，请求实时转发。

拿一把 key

  1. 登录 /login。[登录方式：公司 OAuth 还是邮箱账号、首次登录是否自动建号——管理员填]。这台机器不开放自助注册，要 key 先登录。
  2. 进 /dashboard，打开 /keys，新建一把 key。
  3. 选分组，这一项必填。一个分组对应一类上游账号（Claude 系、GPT-Codex 系、Gemini 系各归各的），也决定这把 key 打 /v1/models 时看到哪些模型。协议不用管：/v1/messages 和 /v1/responses 网关都收，再按分组翻译给上游。清单以新建表单里的下拉为准；一把 key 只属于一个分组，想用两个池就开两把。
  4. 给它起个认得出用途的名字：claude-code-mac、cursor、ci-eval。以后要停哪一把，你自己就能定位。
  5. key 在 /keys 列表里随时可以整条复制回来，丢了不用重建。也正因为如此，能登录你账号的人就能拿走你所有的 key——登录密码放进密码管理器，key 按用途分开开几把。

按机器或按项目分开开几把。某一把泄漏时只吊销那一路，别的照跑。

三条底线：

  • 不提交进仓库。
  • 不贴进公开频道。
  • 不把 key 转给别人——对方的用量会记在你头上，包括他半夜跑的那轮压测。

接上去

改两个环境变量，别的什么都不用动。哪一对，看客户端，不看分组。

Claude Code

export ANTHROPIC_BASE_URL=https://spool.corp.internalexport ANTHROPIC_AUTH_TOKEN=<你的 key>

Codex / Cursor / OpenAI SDK

export OPENAI_BASE_URL=https://spool.corp.internal/v1export OPENAI_API_KEY=<你的 key>

自检

curl -s $OPENAI_BASE_URL/models -H "Authorization: Bearer $OPENAI_API_KEY" | head# 回一个模型列表就算接上了。401 是 key 不对；403 / 429 / 503 见「公平使用」。# 只配了 ANTHROPIC_* 的，把地址换成 $ANTHROPIC_BASE_URL/v1/models，key 用 $ANTHROPIC_AUTH_TOKEN。

两条细节会一直引发工单：

  • 地址末尾不要带斜杠。
  • 模型名照 /v1/models 的返回原样填，网关不改名。

以控制台 /keys 页面显示的地址为准。这里写的和那边不一样时，信那边。

池子里有什么

可用模型以 GET /v1/models 的返回为准，那是唯一不会过期的清单。注意范围：它返回的是你这把 key 所属分组能用的模型，不是整池——分组不同，列表不同；要看别的分组，用那个分组的 key 再打一次。这一页不列表，免得过期骗人。

池子里大致三类，哪一类归你，看建 key 时选的分组：

  • 写代码的：Claude 系、GPT-Codex 系。
  • 长上下文通用的：Gemini 系。
  • 试验性接入的：Antigravity 等，随时可能下线。

model id 直接抄 /v1/models 的返回，不要凭记忆手写——上游改名的频率比你想象的高。

某个模型突然 404，先看 message：写着 not available for this group 的，是这个模型不在你分组的白名单里，换分组，或找 [平台组 / 填负责人] 加；其余的 404 通常是上游改了 id，或者这条线暂时被摘掉了，打一次 /v1/models 核对。

公平使用，以及谁在管

池子是共享的，额度是按人的。用量在控制台看得到；不想登录就用 用量查询，输入 key 查自己那一份。

额度用完不降级、不静默截断——你会看到报错，不会看到胡话。报错先看 body 里的 code，别只看状态码：

  • 429 且 code 带 QUOTA_EXHAUSTED 或 USAGE_LIMIT_EXCEEDED（Codex 那条路上写成 insufficient_quota）：额度用完。退避重试没有用，去找 [平台组 / 填负责人]。
  • 429 且 code 是 USER_RPM_EXCEEDED 或 GROUP_RPM_EXCEEDED：限速打满。退避几秒重试。
  • 403 且 code 是 INSUFFICIENT_BALANCE：账户余额不足。同样去要额度。
  • 503：池里能跑这个模型的账号暂时都不可用。退避重试；一直 503 就去群里说。

[配额策略：每人多少额度、由谁批、是否在 [每月 1 号] 复位——由管理员在这里写明，不要让同事靠猜]

跑批量任务或压测前在群里说一声，错开高峰。不要用交互用的 key 跑 CI，单独开一把。一把 key 对应一个用途。

上游账号偶尔会掉。spool 会把它摘掉，换池里别的账号重试；你可能感觉到一次重试的延迟。全都掉了的时候你拿到的是 503，不是变慢。
