# 排行榜模式为三档暴露递增，实名展示需用户自选

> **2026-09-12 部分被 ADR-0004 取代**：昵称展示改为默认开启的 opt-out 开关。本 ADR 里「实名必须自选 / 默认关闭」的论证以 ADR-0004 为准，其余部分（三档递增、默认 `off`、fail-closed、禁止「User #id」兜底）继续有效。

仓库里已有的用户可见排行（渠道监控 V2 的用户 tab）对非管理员一律匿名并把绝对用量清零，注释写明是防止用户反推站点规模；排行榜没有照搬这一先例，而是让管理员在 `off` / `anonymous` / `named` 三档之间选择：`anonymous` 只给假名、相对第一名的百分比和分档的参与人数；`named` 才显示 username 和精确数值，且只对在个人资料里开启「实名参与」的用户实名，其他人仍是假名。这样做是因为 sub2api 由不同运营者部署，公开中转站与内部团队对「能否看到别人名字和用量规模」的要求截然相反，单一策略无法两头兼顾；而实名必须自选，是因为本仓库的 username 大多由 OAuth 静默回填（钉钉企业模式下就是真实姓名，Google 分支甚至可能落到邮箱全文），把它直接推上全站榜单等于未经同意公开第三方身份。名字一旦公开就无法收回，所以默认档是 `off`，读取设置失败也按 `off` 处理，与监控开关的 fail-open 相反。

## Considered Options

- 布尔开关 + 复用 username：否决，没有「开榜但不暴露规模」这一档，且会被动公开 OAuth 回填的真实姓名。
- 完全照监控先例，永远匿名并抹掉数值：否决，排行榜退化成「我在哪」，失去社交意义。
- 拆成身份可见性与数值可见性两个正交设置：否决，管理员心智负担翻倍，三档递增已覆盖真实需求。
- 新增独立的「榜单展示名」字段并强制首次设置：否决，v1 用 username + 自选开关 + 校验已够用，字段可日后再加。

## Consequences

- `named` 档下关掉了昵称展示的用户仍以假名配精确数值出现，理论上可被熟人对数反查；这是管理员选择最开放档时接受的残余风险，设置项旁需写明。
- 用户 id 永不出现在展示名里，「User #id」这类兜底被明确禁止。
