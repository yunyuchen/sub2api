# 排行榜昵称展示默认开启，改为 opt-out

ADR-0002 把 `users.leaderboard_named_participation` 定为默认关闭的自选开关，理由是 username 大多由 OAuth 静默回填，未经同意推上全站榜单等于公开第三方身份。实际跑起来之后这一档把榜单变成了一整屏假名：默认没人开，`named` 档下所有人仍然是「用户 #N」，页面上唯一的真名是查看者自己，社交意义归零。这次把默认值翻成 `true`，并用迁移 240 把既有用户一并回填为 `true`；同时把假名文案从「用户 #N」改成「第 N 位」（`Row N`），因为 N 是榜单序号（Ordinal）而不是 user_id，旧写法会被读成用户编号。开关本身、校验规则与渲染时的二次校验都不动，只是从 opt-in 变成 opt-out：个人资料上的文案改为「在排行榜显示我的昵称」，不接受的用户自己关掉即可。之所以敢这么翻，是因为 `named` 档本身仍是管理员显式选出的最开放档（默认档仍是 `off`），而 username 校验里的 `@` 规则会把邮箱形态的回填值挡在实名形态之外——落到榜单上的只可能是通过校验的昵称。

## Considered Options

- 维持 opt-in，靠页面引导用户去开：否决，引导要占页面位置且转化率不可控，榜单在转化起来之前一直是假名屏。
- 默认开，但只对新用户生效，存量用户维持关：否决，同一个站点里新老用户的展示规则不一致，「第 N 位」与真名混排会被读成两类账号。
- 新增独立的「榜单展示名」字段并要求首次进入时设置：否决，理由同 ADR-0002——多一个字段与一个强制步骤，收益不足。
- 默认开且移除开关：否决，OAuth 回填真名的风险仍在，退出通道必须保留。

## Consequences

- 本 ADR 在「实名是否需要用户自选」这一点上取代 ADR-0002；ADR-0002 的其余部分（三档递增、默认 `off`、fail-closed 读取、禁止「User #id」兜底）继续有效。
- ADR-0002 Consequences 里那条「`named` 档 + 今日窗口构成粗粒度活动时间线，视为用户开启实名时的同意范围」的论证不再成立：默认开启之后没有这份同意。管理端 `named` 档的风险说明因此改写为「昵称展示默认开启，不接受的用户需自行到个人资料关闭」，并指向 opt-out 路径。
- 部署到已有用户的站点时，迁移 240 会一次性把所有人改成「显示昵称」。运营者若不接受这一点，MUST 在切到 `named` 档之前先通知用户；`off` 与 `anonymous` 两档下这个列的值不产生任何对外可见的效果。
