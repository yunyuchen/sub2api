Claude Code 新手指南：安装、接入 spool、第一个项目

2026-09-12 Claude CodeSetup

开始之前

spool 是团队内部自建自运维的 AI 网关。账号由管理员创建，页面上没有自助注册入口。拿到账号后先在 /login 登录，再去 /keys 建一把 API Key。

建 Key 的时候必须选一个分组，分组决定这把 Key 能看到哪些模型，也就决定了你在 Claude Code 里能填哪些模型名。Key 建好之后可以随时回 API Keys 列表再复制一次，第一次没存下来也不要紧，不用重新创建。

整个流程大概十分钟，其中八分钟花在装 Node.js 上。

装 Node.js 和 Claude Code

Claude Code 是 Anthropic 官方的命令行工具，跑在 Node.js 上（需要 18 或更高版本），用 npm 全局安装。

macOS

/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
brew install node
node -v && npm -v

Windows

以管理员身份打开 PowerShell（需要 Windows 10 1809 或更高），用 winget 或 Chocolatey 装 Node.js：

winget install OpenJS.NodeJS.LTS
# 或者
choco install nodejs-lts

node -v
npm -v

装 CLI

npm install -g @anthropic-ai/claude-code
claude --version

macOS 上装不上，十有八九是全局目录没有写权限。比起直接加 sudo，更省心的做法是把 npm 的全局目录挪到用户目录下，再把它的 bin 加进 PATH，以后升级也不用再要权限。拉包慢可以临时换个源：npm config set registry https://registry.npmmirror.com。

版本太旧会缺一些命令和参数，隔一阵子更新一次即可。

接入 spool

Claude Code 只认两个东西：网关地址和凭证。地址原样填，不要加 /v1，带 /v1 是 OpenAI 风格客户端的写法，两边不要抄串。

# ~/.zshrc 或 ~/.bashrc
export ANTHROPIC_BASE_URL="https://spool.corp.internal"
export ANTHROPIC_AUTH_TOKEN="替换成你在 /keys 里创建的 Key"

写完执行 source ~/.zshrc 让它立刻生效，新开的终端会自动带上。ANTHROPIC_API_KEY 同样被识别，两个变量填一个就行，不用都填，也不要填成两个不一样的值。

Windows 上写进 PowerShell Profile：先 notepad $PROFILE 打开（文件不存在会自动创建），加两行再重开终端。

$env:ANTHROPIC_BASE_URL = "https://spool.corp.internal"
$env:ANTHROPIC_AUTH_TOKEN = "替换成你的 Key"

如果不想污染全局环境，也可以把这两项写进 ~/.claude/settings.json 的 env 字段，只对 Claude Code 生效。机器上同时有别的工具要连别的地址时，这样更干净。

配没配对用 claude doctor 看一眼，它会顺带检查安装状态和连通性。检测不到凭证时，直接运行 claude 会进入登录引导，但团队里统一用环境变量更省事，也方便换 Key。

确认自己能用哪些模型

模型清单没有第二份真相，以网关返回的为准：

curl -s https://spool.corp.internal/v1/models \
  -H "Authorization: Bearer $ANTHROPIC_AUTH_TOKEN"

返回的是你这把 Key 所属分组的可用模型。模型 id 原样透传给上游，网关不做改名，所以清单里写什么就填什么。填清单以外的名字会收到 404，消息里带 not available for this group，这时候不是名字拼错，是分组没放行。

第一个项目

  1. cd 到项目目录，确认 git 工作区是干净的，然后直接跑 claude。干净的工作区是你复核它改了什么的前提。
  2. 先执行 /init，让它通读仓库生成 CLAUDE.md。这份文件之后每轮对话都会自动带上，值得花几分钟手工修一遍，把构建命令、测试命令、目录约定写准。
  3. 第一个问题不要让它改代码。先问「这个仓库的入口在哪、测试怎么跑」，看它对代码库的理解对不对，比直接派活更能暴露上下文问题。
  4. 再让它改一处小东西，改完用 git diff 自己过一遍再接受。
  5. 话题切换的时候用 /clear 清掉上下文，旧任务的残留会让它跑偏。想知道花了多少，用 /cost，或者去 /key-usage 按 Key 查明细。

用下来最有效的习惯只有一条：一次只交代一件事。任务拆得越碎，它跑偏的概率越低，你复核的成本也越低。让它一口气重构三个模块，最后往往是你自己回滚。

几条提醒

  • Key 不要写进代码、不要提交到 git，只放在 shell 配置或已被 .gitignore 忽略的 .env 里。
  • 本地、CI、服务器各建一把 Key，出问题好定位，需要吊销时也不会互相牵连。
  • 报错先看 HTTP 状态码再看 error.code，401、403、404、429、503 的处理方式完全不同，别一律当成网络抖动重试，具体见《API 报错怎么读》。
  • Key 疑似泄露，或者遇到额度、余额相关的报错，都直接找管理员，这类问题在本地改不好。

Codex 入门：CLI 安装、config.toml 与常见坑

2026-09-12 CodexSetup

装 CLI

Codex 是 OpenAI 官方的命令行工具，和 Claude Code 一样依赖 Node.js。Node 装好之后：

npm install -g @openai/codex
codex --version

接入 spool 之前，先确认你已经在 /keys 建好了 API Key，并且记住它所属的分组，分组决定你能填哪些模型 id。

它有两种用法：直接敲 codex 进交互式会话，或者用 codex exec 跑一条命令就退出，后者适合塞进脚本。两种用法读的是同一份配置。

配置目录

Codex 的配置在用户目录下的 .codex 文件夹，macOS 和 Linux 是 ~/.codex，Windows 是 %USERPROFILE%\.codex。目录不存在就自己建：

mkdir -p ~/.codex

Finder 默认不显示点开头的目录，按 Command+Shift+. 可以切换显示，或者干脆全程在终端里操作，反而快。

config.toml

新建 ~/.codex/config.toml，写一个指向 spool 的 provider，再把默认 provider 指过去：

model_provider = "spool"
model = "MODEL_ID"              # 换成 /v1/models 返回的模型 id
model_reasoning_effort = "high"
disable_response_storage = true

[model_providers.spool]
name = "spool"
base_url = "https://spool.corp.internal/v1"
wire_api = "responses"
env_key = "OPENAI_API_KEY"

注意 base_url 末尾的 /v1：Codex 走的是 OpenAI 风格接口，这一段必须带上。Claude Code 那边正好相反，填的是不带 /v1 的裸地址。这是两篇教程之间最容易抄串的一行。

disable_response_storage 建议保持打开，走网关时不要依赖服务端的会话存储。model_reasoning_effort 是思考力度，先用默认值跑通再按任务调。config.toml 里还能配审批策略和沙箱级别，那些和接入无关，等能正常对话了再研究。

凭证放哪

两种写法，选一种，不要两种都写。一是环境变量，配合上面的 env_key：

export OPENAI_BASE_URL="https://spool.corp.internal/v1"
export OPENAI_API_KEY="替换成你的 Key"

二是写进 ~/.codex/auth.json，适合不想动 shell 配置的机器：

{
  "OPENAI_API_KEY": "替换成你的 Key"
}

模型 id 怎么定

不要凭印象写。网关把模型 id 原样透传给上游，能不能用只取决于你所在分组的白名单：

curl -s https://spool.corp.internal/v1/models \
  -H "Authorization: Bearer $OPENAI_API_KEY"

返回里有的才能填。填错会拿到 404，消息里带 not available for this group，这说明模型存在但你的分组没放行，改拼写没用，得找管理员调分组。

常见坑

  • base_url 漏了 /v1。最常见的一个，表现是路径 404，或者客户端报一个看起来像网络故障的错。
  • 表名对不上。[model_providers.spool] 里的 spool 必须和顶部 model_provider 的值一字不差。写错了 Codex 找不到 provider，报的错和连不上网长得很像，能耗掉不少时间。
  • 改完配置没重启。Codex 只在启动时读一次配置文件，正在跑的会话不会热加载。改完退出重开，再验证。
  • auth.json 和环境变量都配了。两处同时存在时以哪边为准取决于版本，典型症状是「明明换了 Key 还是旧的在生效」。只留一种。
  • TOML 写坏了。字符串要用英文双引号，表头要顶格，注释用 #。从聊天窗口粘贴时特别留意中文引号和全角空格。
  • 公司代理拦截。设了 HTTPS_PROXY 的机器记得把内网域名加进 NO_PROXY，否则请求会先绕出公网再被挡回来。

跑起来之后

Codex 会读工作目录里的 AGENTS.md，把项目约定、构建命令、代码风格写进去，比每次在对话里重复交代靠谱。这份文件和接入无关，但决定了它在你仓库里好不好用。

如果你同时接了几个网关，或者一个网关里要在不同模型之间来回切，可以在 config.toml 里配多个 provider，用命令行参数指定这次用哪个，省得反复改文件。改哪一种方式都记得重启。

验证

codex exec "用一句话说明你是谁"

能正常返回就算通了。如果报错，先分清是网关侧还是 Codex 侧：用上面那条 curl 打一次 /v1/models，能返回模型清单就说明 Key 和地址都没问题，剩下的错只可能出在 config.toml。

再往下就是看状态码：401 是 Key 不对，404 多半是模型名或 base_url，403 是余额，429 和 503 分别对应额度、限速和上游可用性，各自的处理方式见《API 报错怎么读》。

API 报错怎么读：401 / 403 / 429 / 404 / 503 排查指南

2026-09-12 Error CodesTroubleshooting

先看两个字段

网关的错误都带结构，排查只需要两样东西：HTTP 状态码，和响应体里的 error.code 或 error.type。同一个状态码下语义可能完全不同，尤其是 429，只看状态码会把「该重试」和「重试也没用」混为一谈，这是这套错误码里最贵的一个误判。

命令行里最快的抓法是加 -i 把响应头一起打出来：

curl -i https://spool.corp.internal/v1/models \
  -H "Authorization: Bearer $ANTHROPIC_AUTH_TOKEN"

图形客户端经常只显示一句「请求失败」，把原始响应吞掉。这种时候先用 curl 复现一次，拿到真正的状态码再判断，比在客户端里反复点重试有用得多。

401 凭证不对

Key 写错、被删、已过期，或者压根没传上去。先排除几种低级情况：复制时带了首尾空格或换行、环境变量名拼错、shell 配置改了但没有 source、客户端里存的还是上一把 Key、同时设了两个变量而它们的值不一样。确认无误后回 /keys，列表里随时可以重新复制完整的 Key，不需要重新创建，也不用担心之前没保存。

403 + INSUFFICIENT_BALANCE 余额不足

账户余额已经低于可用线，请求在到达上游之前就被拦下了。这不是你能在客户端里改好的事，换模型、换客户端都没用，找管理员。

429 要分两种看

额度用完：QUOTA_EXHAUSTED / USAGE_LIMIT_EXCEEDED

走 Codex 的 OpenAI 风格路径时，同一类情况的 type 是 insufficient_quota。这几个码的含义是配额已经耗尽，重试没有任何意义，等一会儿也不会自己好。脚本里尤其要把它和限速区分开，否则会在一个必然失败的请求上一直退避重试到超时，日志里还只留下一串 429，看不出真正原因。处理方式只有一个：找管理员加额度。

限速：USER_RPM_EXCEEDED / GROUP_RPM_EXCEEDED

单位时间内请求数超了。前者是你这把 Key 自己超的，后者是整个分组一起超的。这种是暂时的，退避重试就行，建议指数退避加随机抖动，别用固定间隔硬打，固定间隔的并发很容易在下一个窗口再次一起撞上。如果看到的是 GROUP，说明同组同事也在跑，跟他们说一声比继续重试有效。

404 模型不在分组白名单

消息里带 not available for this group，意思是模型名本身没问题，但你这把 Key 所在的分组没放行它。不要改拼写反复试，直接问网关：

curl -s https://spool.corp.internal/v1/models \
  -H "Authorization: Bearer $ANTHROPIC_AUTH_TOKEN"

返回的就是你能用的全部模型，id 原样透传，清单里怎么写就怎么填。确实需要清单之外的模型，找管理员调整分组。

503 暂时没有可用上游

当前没有可调度的上游账号，可能是都在忙，也可能是都被临时标记为不可用。和限速一样退避重试，持续几分钟不恢复就告诉管理员，这通常意味着上游侧需要人介入。

一张对照表

状态码关键字段含义怎么办
401—Key 不对或没传回 /keys 重新复制
403INSUFFICIENT_BALANCE余额不足找管理员
429QUOTA_EXHAUSTED / USAGE_LIMIT_EXCEEDED（Codex 路径为 insufficient_quota）额度用完别重试，找管理员
429USER_RPM_EXCEEDED / GROUP_RPM_EXCEEDED触发限速退避后重试
404not available for this group模型不在分组白名单查 /v1/models
503—暂时没有可用上游账号退避后重试

写重试逻辑时

只对 429 限速和 503 重试，其余一律立刻失败，并把 error.code 原样打进日志。把 429 当成一类统一重试，是最容易踩的坑。另外流式请求的错误可能在连接建立之后才以事件的形式发回来，客户端不要只在收到响应头那一刻判断成败，否则会出现「开头是 200，中途断了，程序却认为成功」。

需要找管理员的时候

把这几样一起给出来，一轮就能定位：出错时间、状态码、error.code、用的模型 id、Key 的名称（不是 Key 本身）、以及是哪个客户端。任何情况下都不要把完整的 Key 贴进聊天窗口，需要确认是不是 Key 的问题，说名称就够了。

客户端接入指南：Cherry Studio、Chatbox、CC Switch 怎么填

2026-09-12 ClientsSetup

只需要记住一条规则

spool 同时兼容两种协议风格，填地址的时候按客户端类型选：

  • Anthropic 风格（Claude API、Claude Code）：https://spool.corp.internal，原样填，不加后缀。
  • OpenAI 风格（OpenAI API、Codex、绝大多数第三方客户端）：https://spool.corp.internal/v1。

Key 在 /keys 创建，同一把 Key 两种风格都能用，不需要为不同模型族分别建。列表里随时能再复制一次，不用担心弹窗关掉就没了。

还有一条同样重要：模型 id 由网关原样透传，能用哪些取决于 Key 所属的分组。填之前先拿清单，省掉一整轮猜名字：

curl -s https://spool.corp.internal/v1/models \
  -H "Authorization: Bearer 你的Key"

Cherry Studio

桌面客户端，Windows / macOS / Linux 都有。

  1. 点左下角齿轮进设置，左侧选「模型服务」。
  2. 在列表底部点添加，服务商类型选 OpenAI，名称随便填一个自己能认出来的，比如 spool。
  3. API 地址填 https://spool.corp.internal/v1，API Key 填你的 Key。
  4. Cherry Studio 不会自动拉取模型列表，需要在服务商详情页手动「添加模型」，把 /v1/models 返回的 id 一条条填进去。填的是 id，不是展示名。
  5. 打开详情面板右上角的启用开关，回到对话界面，从模型下拉里选中刚加的那个。

想用 Anthropic 原生风格，把服务商类型换成 Anthropic，地址改成不带 /v1 的那个，其余一样。

Chatbox

跨平台，桌面端和手机端配置方式一致。进设置里的模型页，按你要用的模型族选提供方：

  • Claude 系列：提供方选「Claude API」，API 地址填 https://spool.corp.internal。
  • GPT 系列：提供方选「OpenAI API」，API 地址填 https://spool.corp.internal/v1。

两种都用同一把 Key，模型名从 /v1/models 里抄。保存后新建一个会话发条消息，能回就是通了。手机端如果连的是内网地址，记得先确认设备在公司网络或已经连上内网通道，不然会卡在连接超时，跟配置本身没关系。

有些客户端会自己在你填的地址后面补路径。如果照上面填完立刻 404，把 /v1 加上或者去掉再试一次，多数情况就是这一段重复或者缺失。判断依据很简单：报 404 而不是 401，说明 Key 是对的，问题在路径。

CC Switch

这个不是聊天客户端，而是管命令行工具配置的桌面应用。它直接改写 ~/.claude/settings.json 和 ~/.codex/config.toml、~/.codex/auth.json，用来在多个供应商之间一键切换。手上同时接了几个网关的人值得装一个。

前提是本机已经装好了对应的 CLI，否则它没有可管的对象。

Claude Code 供应商

  • 名称：spool
  • ANTHROPIC_BASE_URL：https://spool.corp.internal
  • ANTHROPIC_AUTH_TOKEN：你的 Key

Codex 供应商

  • 名称：spool
  • base_url：https://spool.corp.internal/v1
  • wire_api：responses
  • model：/v1/models 里的某个 id
  • OPENAI_API_KEY：你的 Key

切换只是改文件，已经开着的 CLI 不会感知到。切完记得把终端里的 claude 或 codex 退出重开，否则你会看到「明明切过去了还是走旧配置」。另外它改的是全局配置文件，如果你之前手动在这些文件里写过别的东西，切换前先备份一份。

其他 OpenAI 兼容的客户端和 SDK

规则完全一样：地址 https://spool.corp.internal/v1，凭证放 OPENAI_API_KEY。官方 SDK 里就是 base_url 和 api_key 两个参数，IDE 插件通常叫「自定义 API 地址」或「Custom endpoint」。凡是能填这两项的，都能接。

验证和排错

任何客户端配完，都用同一个动作验证：新建会话，发一条最短的消息，别一上来就贴长文档试。失败时看状态码，401 是 Key，404 多半是模型名或地址里的 /v1，403 是余额，429 和 503 分别对应额度、限速和上游可用性，逐个的判断方法见《API 报错怎么读》。额度和余额相关的报错在客户端里改不好，找管理员。

最后一条：手机上的客户端和共用的机器同样在存你的 Key。这类设备单独建一把，不要和本地开发共用，丢了也只需要吊销一把。
