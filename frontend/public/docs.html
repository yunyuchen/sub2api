使用教程/Claude Code 配置

Claude Code 配置

这一章从零走一遍：装 Node.js、装 Claude Code CLI、把它指向 spool 网关，最后发一句话确认真的通了。Mac 和 Windows 分开写，按自己的系统看一节就够。

说明：开始之前你需要一把 API Key。账号由管理员统一开通，平台不提供自助注册；登录后到「API Keys」页面新建一把即可。新建时必须选一个分组，分组决定这把 Key 能看到哪些模型。Key 建好之后可以随时回列表里再复制一次，当场没记下来也没关系。

说明：整章只涉及两个环境变量：ANTHROPIC_BASE_URL 填 https://rq.yunyc.work，ANTHROPIC_AUTH_TOKEN 填你的 Key。剩下的都是把这两行放到正确的位置。

Mac 安装教程

第一步：用 Homebrew 安装 Node.js

Claude Code 跑在 Node.js 上，需要 18 或更高版本。用 Homebrew 装最省事。还没有 Homebrew 就先装它：

/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

然后装 Node.js，顺手确认版本：

brew install node

node -v   # 需要 v18 以上
npm -v

提示：机器上已经有 Node.js 就跳过这步。只要 node -v 不低于 18 就够用，不必为了这个重装或升级。

第二步：安装 Claude Code

npm install -g @anthropic-ai/claude-code

装完检查一下：

claude --version
claude doctor

claude doctor 会检查安装方式、版本和自动更新是否正常，有问题它会把原因直接写出来，比自己猜快得多。

注意：npm install -g 报权限错误时别急着加 sudo，那会让之后的自动更新也要 root。把 npm 的全局目录挪到用户目录下更干净。

npm config set prefix ~/.npm-global
echo 'export PATH="$HOME/.npm-global/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc

npm install -g @anthropic-ai/claude-code

提示：npm 下载慢的话可以临时换个源：npm config set registry https://registry.npmmirror.com。

第三步：配置 BASE_URL 和 AUTH_TOKEN

把两行写进 ~/.zshrc（还在用 bash 就写 ~/.bashrc），以后每开一个终端都自动带上：

# spool - Claude Code
export ANTHROPIC_BASE_URL="https://rq.yunyc.work"
export ANTHROPIC_AUTH_TOKEN="sk-换成你自己的 Key"

保存后重载，并确认变量确实读到了：

source ~/.zshrc

echo $ANTHROPIC_BASE_URL
echo $ANTHROPIC_AUTH_TOKEN

说明：地址写到域名为止，不要加 /v1，也不要带结尾斜杠 —— Claude Code 会自己拼接后面的路径。只有 OpenAI 风格的客户端（比如 Codex）才需要在地址后面补 /v1。

提示：用 ANTHROPIC_API_KEY 代替 ANTHROPIC_AUTH_TOKEN 同样能通，网关两种都认。二选一就好，两个都设反而容易搞不清当前生效的是哪个。

注意：如果这台机器以前用官方账号登录过 Claude Code，先执行 claude 进入交互界面输入 /logout，退出重开。否则它会继续走原来的登录态，环境变量看着设了却不起作用。

第四步：发一句话验证

claude -p "用一句话说明你是谁"

能拿到一句正常回答，链路就通了。想顺便确认这把 Key 能用哪些模型，列一下清单：

curl https://rq.yunyc.work/v1/models \
  -H "Authorization: Bearer $ANTHROPIC_AUTH_TOKEN"

返回里的 id 就是可以直接填给客户端的模型名，网关原样透传不做改写。清单内容取决于你的 Key 所在分组，以这个接口的返回为准。

Windows 安装教程

说明：下面的步骤适用于 Windows 10（1809 及以上）和 Windows 11 的 PowerShell。如果你平时在 WSL 里写代码，那就在 WSL 内部按上面 Mac 那一节的做法配置：Windows 侧的环境变量不会自动带进 WSL。

第一步：用 Chocolatey 安装 Node.js

  1. 右键开始菜单，选「终端（管理员）」或「Windows PowerShell（管理员）」。
  2. 在管理员窗口里装 Chocolatey，再用它装 Node.js LTS。
Set-ExecutionPolicy Bypass -Scope Process -Force
irm https://community.chocolatey.org/install.ps1 | iex

choco install nodejs-lts -y

装完关掉管理员窗口，重新开一个普通 PowerShell，确认命令已经进了 PATH：

node -v
npm -v

提示：不想装 Chocolatey 的话，去 nodejs.org 下载 LTS 安装包一路下一步也一样，后面的步骤完全不变。

第二步：安装 Claude Code

npm install -g @anthropic-ai/claude-code

claude --version
claude doctor

注意：提示「无法识别 claude 命令」多半是 npm 的全局目录没进 PATH。先关掉终端重开一次；还不行就执行 npm config get prefix，把输出的路径加进用户 PATH 再重开。

第三步：配置环境变量

两种方式，选一种就够，不要两边都写。

方式一：写进 PowerShell Profile。适合常用命令行的人。

notepad $PROFILE

文件不存在时记事本会问是否新建，选「是」。如果保存失败，先执行 New-Item -ItemType File -Path $PROFILE -Force 把文件建出来再编辑。在末尾补上两行并保存：

# spool - Claude Code
$env:ANTHROPIC_BASE_URL  = "https://rq.yunyc.work"
$env:ANTHROPIC_AUTH_TOKEN = "sk-换成你自己的 Key"

重开 PowerShell 自动生效，想当场生效就执行 . $PROFILE。

方式二：系统环境变量面板。适合不常开终端的人，配一次所有程序都能读到。

  1. 在任务栏搜索「环境变量」，打开「编辑账户的环境变量」。
  2. 在上方「用户变量」区域点「新建」，按下表加两条。
  3. 确定保存后，把已经打开的终端和编辑器全部关掉重开，新变量才会被读到。
变量名变量值
ANTHROPIC_BASE_URLhttps://rq.yunyc.work
ANTHROPIC_AUTH_TOKEN你在 API Keys 页面创建的 Key

同样的事也可以用命令一次写好，效果和图形界面完全一致：

setx ANTHROPIC_BASE_URL "https://rq.yunyc.work"
setx ANTHROPIC_AUTH_TOKEN "sk-换成你自己的 Key"

说明：setx 只对之后新开的进程生效，当前这个窗口里 echo $env:ANTHROPIC_BASE_URL 仍然是空的，属于正常现象，重开一个窗口再看。

第四步：发一句话验证

echo $env:ANTHROPIC_BASE_URL
echo $env:ANTHROPIC_AUTH_TOKEN

claude -p "用一句话说明你是谁"

确认这把 Key 能用的模型清单：

curl.exe https://rq.yunyc.work/v1/models -H "Authorization: Bearer $env:ANTHROPIC_AUTH_TOKEN"

提示：PowerShell 里的 curl 是 Invoke-WebRequest 的别名，行为和真正的 curl 不一样，所以上面写的是 curl.exe。

指定模型（可选）

不设的话 Claude Code 用它自己的默认模型。想固定成某一个，把 /v1/models 返回的 id 原样填给 ANTHROPIC_MODEL：

export ANTHROPIC_MODEL="从 /v1/models 返回里挑一个 id"

网关不改写模型名，填什么就转发什么。填了分组里没有的模型会直接返回 404，不会悄悄替换成别的。

报错对照表

下面这些是网关返回的状态，和模型本身无关。先看清是哪一种，再决定要不要重试。

返回含义怎么处理
401Key 不对Key 写错或已被删除。回 API Keys 页面重新复制，注意别把引号、空格一起粘进去。
429 + QUOTA_EXHAUSTED / USAGE_LIMIT_EXCEEDED额度用完了重试没有意义，找管理员。
429 + USER_RPM_EXCEEDED / GROUP_RPM_EXCEEDED触发频率限制等几秒再发，或降低并发数量，会自己恢复。
403 + INSUFFICIENT_BALANCE余额不足找管理员。
404，带 not available for this group模型不在你所属分组的白名单里换一个 /v1/models 里列出的模型，需要开通就找管理员。
503当前没有可用的上游账号稍等再试。持续出现就找管理员。

注意：Key 等同于你的账号使用权，不要提交进 Git 仓库，也不要贴在群里。写进 ~/.zshrc 或 PowerShell Profile 之后，项目代码里就不需要再出现明文 Key。万一外泄，去 API Keys 页面把它删掉并新建一把。

Codex 安装配置

Codex 是 OpenAI 官方的命令行编码工具。把它的模型服务商指向 spool，就能用团队的 API Key 调用你所在分组里的模型，不需要 OpenAI 官方账号，也不用改动项目里的任何代码。

开始之前需要两样东西：一个 spool 账号（由管理员创建，不支持自助注册），以及一把在 /keys 页面创建的 API Key。创建 key 时必须选择分组，分组决定这把 key 能调用哪些模型。key 创建后可以随时回 API Keys 列表再复制一次，不必担心当场没记下来。

环境准备

Codex CLI 通过 npm 分发，先确认本机有 Node.js 和 npm。建议使用 Node.js 20 或更高版本，过低的版本可能装不上或启动即报错。

node -v
npm -v

如果命令不存在，先安装 Node.js：macOS 可以用 Homebrew 执行 brew install node，Windows 可以用 Chocolatey 执行 choco install nodejs-lts，或者直接从 Node.js 官网下载安装包。装完重开一个终端窗口再验证。

安装 Codex

npm install -g @openai/codex

安装完成后验证：

codex --version

macOS 或 Linux 下若提示权限不足，不要直接加 sudo。更稳妥的做法是把 npm 全局目录换到用户目录下（npm config set prefix ~/.npm-global，再把 ~/.npm-global/bin 加进 PATH），或者用 nvm 管理 Node.js。

创建配置文件

Codex 的配置放在用户目录下的 .codex 文件夹里。先建好目录：

mkdir -p ~/.codex

Windows 下对应的路径是 %USERPROFILE%\.codex\，在 PowerShell 里执行 mkdir $env:USERPROFILE\.codex 即可。

macOS 的访达默认不显示以点开头的文件夹，按 Command + Shift + . 可以切换显示；用终端创建和编辑则不受影响。

然后创建 ~/.codex/config.toml，写入下面的内容：

model_provider = "spool"
model = "MODEL_ID"
model_reasoning_effort = "high"
disable_response_storage = true

[model_providers.spool]
name = "spool"
base_url = "https://rq.yunyc.work/v1"
wire_api = "responses"
env_key = "OPENAI_API_KEY"

逐项说明：

  • model_provider：指定使用哪个服务商，值要和下面 [model_providers.xxx] 的名字一致。
  • model：默认使用的模型 id。把 MODEL_ID 换成你分组里的真实模型 id，取值方式见下一节。
  • base_url：spool 的地址加上 /v1。Codex 属于 OpenAI 风格的客户端，路径后缀不能省，写成 https://rq.yunyc.work 会 404。
  • wire_api：请求协议。Codex 默认走 OpenAI 的 Responses 协议，保持 "responses" 即可。
  • env_key：告诉 Codex 从哪个环境变量里读 API Key，我们用标准的 OPENAI_API_KEY。
  • disable_response_storage：关闭服务端会话存储。开启时 Codex 会依赖上一次响应的 id 续接对话，经网关转发容易失败，设为 true 让每次请求都带完整上下文。
  • model_reasoning_effort：推理强度，可选 minimal / low / medium / high，只对支持推理的模型有意义；如果选定的模型不支持，删掉这一行即可。

填入 API Key

在 /keys 页面复制你的 key，然后写进 shell 配置文件，让每个新开的终端都能读到。macOS 默认是 zsh：

echo 'export OPENAI_API_KEY="sk-你的key"' >> ~/.zshrc
source ~/.zshrc

用 bash 的话把 ~/.zshrc 换成 ~/.bashrc。Windows 在 PowerShell 里执行：

setx OPENAI_API_KEY "sk-你的key"

setx 只对之后新开的窗口生效，执行完请重开一个终端。

也可以不用环境变量，改成把 key 写进 ~/.codex/auth.json：

{
  "OPENAI_API_KEY": "sk-你的key"
}

读不到环境变量时 Codex 会回落到这个文件。IDE 扩展的场景下这种写法更省事，原因见「Codex IDE 配置」一章。两种方式任选其一。两处同时存在时以哪边为准取决于 Codex 版本，容易出现「换了 Key 还是旧的在生效」，所以只留一种。

key 等同于你的账号凭证，不要提交进 git 仓库、不要贴在聊天记录里。建议给不同环境（本机、CI、服务器）各建一把 key，需要吊销时互不影响。怀疑泄露就回 API Keys 页面删掉重建，并知会管理员。

选择模型

模型 id 由 spool 原样透传，不做改写；你能用哪些，取决于这把 key 所属的分组。用下面的命令拿到权威列表：

curl -s https://rq.yunyc.work/v1/models \
  -H "Authorization: Bearer $OPENAI_API_KEY"

从返回结果里挑一个 id，填回 config.toml 的 model 字段。临时换模型不必改文件，启动时带参数即可：

codex -m 另一个模型id

会话进行中也可以用 /model 命令切换。

如果某个模型在 Responses 协议下报错，可以把该服务商的 wire_api 改成 "chat" 走 Chat Completions 协议，base_url 保持不变。

切换分组

一把 key 只绑定一个分组。需要用到另一个分组的模型时，先在 /keys 页面用那个分组再建一把 key，然后在 config.toml 里配成两套服务商，用 profile 来回切：

profile = "main"
disable_response_storage = true

[profiles.main]
model_provider = "spool"
model = "MODEL_ID_A"

[profiles.alt]
model_provider = "spool_alt"
model = "MODEL_ID_B"

[model_providers.spool]
name = "spool"
base_url = "https://rq.yunyc.work/v1"
wire_api = "responses"
env_key = "OPENAI_API_KEY"

[model_providers.spool_alt]
name = "spool alt"
base_url = "https://rq.yunyc.work/v1"
wire_api = "responses"
env_key = "SPOOL_API_KEY_ALT"

把第二把 key 导出到 SPOOL_API_KEY_ALT，之后这样启动就走另一个分组：

codex --profile alt

两个服务商的地址完全一样，区别只在读哪个环境变量里的 key。

验证

进入任意项目目录，直接启动：

codex

发一句「请回复你当前运行的模型名称」确认链路通畅。

如果首次启动弹出 ChatGPT 账号登录引导，不要走账号登录，选择使用 API Key 的方式；账号登录会绕开 config.toml 里的服务商配置，请求就不经过 spool 了。确认当前终端里 echo $OPENAI_API_KEY 有值，再重新启动。

Claude Code IDE 配置

CLI 装好以后，编辑器扩展就是在同一套配置上再加一层界面：在侧边栏对话、把选中的代码丢过去、让它直接改文件。扩展本身不需要另外填地址和 Key，它读的就是你在上一章设好的那两个环境变量。

说明：前置条件是先按「Claude Code 配置」装好 CLI，并配好 ANTHROPIC_BASE_URL 和 ANTHROPIC_AUTH_TOKEN。扩展在后台调用的就是本机的 claude，终端里不通，扩展一定也不通。

VS Code 系（VS Code / Cursor / Windsurf / Trae）

这几款都是 VS Code 内核，安装和配置步骤完全一样。

  1. 按 Shift+Cmd+X（Windows 是 Ctrl+Shift+X）打开扩展面板。
  2. 搜索 Claude Code，确认发布者是 Anthropic 再点安装 —— 同名仿冒扩展不少，别装错。
  3. 装完重启编辑器，左侧活动栏会多出 Claude Code 图标。

也可以在终端里一条命令装好：

code --install-extension anthropic.claude-code      # VS Code
cursor --install-extension anthropic.claude-code    # Cursor
windsurf --install-extension anthropic.claude-code  # Windsurf
trae --install-extension anthropic.claude-code      # Trae

说明：Cursor / Windsurf / Trae 用的是 Open VSX 扩展源，不是微软官方市场，偶尔搜不到或者版本偏旧。遇到这种情况从官方渠道下载 .vsix 离线包，再用扩展面板右上角的「…」→「从 VSIX 安装」装上。

让扩展读到环境变量

macOS 上从 Dock 或访达双击启动的应用不会加载 ~/.zshrc，所以扩展可能看不到你配的变量。两种解法，任选其一。

解法一：从终端启动编辑器。在项目目录里执行对应命令，当前 shell 的环境变量会被子进程继承。

code .
cursor .
windsurf .
trae .

解法二：写进 Claude Code 自己的配置文件。和启动方式无关，双击图标也生效，长期用推荐这种。编辑 ~/.claude/settings.json（Windows 在 %USERPROFILE%\.claude\settings.json），文件不存在就新建：

{
  "env": {
    "ANTHROPIC_BASE_URL": "https://rq.yunyc.work",
    "ANTHROPIC_AUTH_TOKEN": "sk-换成你自己的 Key"
  }
}

说明：Windows 通过「环境变量」面板配的是用户级变量，双击图标启动的程序照样能读到，一般不用额外处理。

验证

点活动栏里的 Claude Code 图标打开面板，发一句「用一句话说明你是谁」。有正常回复就说明扩展和网关都通了。面板的默认快捷键是 Cmd+Esc（Windows / Linux 是 Ctrl+Esc）。

JetBrains 系（IDEA / PyCharm / GoLand / WebStorm / Android Studio）

  1. 打开「设置」→「插件」（macOS 是 Preferences → Plugins），切到 Marketplace 标签页。
  2. 搜索 Claude Code，确认发布者是 Anthropic，点 Install。
  3. 重启 IDE，右侧或底部会出现 Claude Code 工具窗口。

插件同样依赖本机 CLI 和同一套环境变量，设置里不需要另填地址或 Key。

注意：macOS 上用 Toolbox 或 Dock 启动的 JetBrains IDE 同样读不到 ~/.zshrc。最省心的做法还是上面那份 ~/.claude/settings.json；临时用的话，在 IDE 内置终端里执行 claude 也行 —— 内置终端走的是登录 shell，变量是齐的。

验证方式一样：在工具窗口里发一句话，或者在内置终端执行 claude -p "用一句话说明你是谁"。

用不起来时先看这几条

  • 面板一直转圈或直接报连接失败。先回终端跑 claude -p "hi"。CLI 也不通，问题在环境变量，回「Claude Code 配置」那一章检查；CLI 通而扩展不通，基本就是启动方式没把变量带进去，用 ~/.claude/settings.json 那一招。
  • 提示要登录 Anthropic 账号。说明它没读到 token，或者本机还留着以前的官方登录态。执行 claude 后输入 /logout，退出重开编辑器。
  • 401。Key 写错或已被删除，回 API Keys 页面重新复制一次。
  • 选不到想要的模型。模型清单由 Key 所属分组决定，以 GET /v1/models 的返回为准，分组里没有的模型会返回 404。需要开通就找管理员。
  • 429 / 403 / 503。含义和处理办法见「Claude Code 配置」章末的报错对照表。

Codex IDE 配置

OpenAI 为编辑器提供了官方 Codex 扩展，装上之后可以在 IDE 侧边栏直接对话、改代码，认证和模型配置与命令行完全共用一套文件，不需要在 IDE 里另填地址和 key。

本章对 VS Code、Cursor、Windsurf、Trae 都适用，步骤一致。

前置条件：请先按「Codex 安装配置」完成 ~/.codex/config.toml，确认命令行里的 codex 已经能正常对话。IDE 扩展读的就是同一个文件。

安装扩展

在 IDE 中按 Shift + Command + X（Windows 和 Linux 是 Ctrl + Shift + X）打开扩展面板，搜索 Codex，选中发布者为 OpenAI 的那个，点击 Install。市场里同名扩展很多，务必确认发布者。

也可以用命令行安装，按你用的 IDE 选一条：

# VS Code
code --install-extension openai.chatgpt

# Cursor
cursor --install-extension openai.chatgpt

# Windsurf
windsurf --install-extension openai.chatgpt

# Trae
trae --install-extension openai.chatgpt

Cursor、Windsurf、Trae 用的是 Open VSX 扩展源，官方扩展有可能还没同步过去。遇到搜不到的情况，可以在 VS Code 官方市场页面右侧点击 Download Extension 拿到 .vsix 文件，再在扩展面板右上角的「…」菜单里选「从 VSIX 安装」离线装上。

装完重启 IDE，左侧活动栏会多出 Codex 图标。

认证与配置

扩展直接读取 ~/.codex/config.toml，Windows 下是 %USERPROFILE%\.codex\config.toml。地址、模型、分组这些都在这个文件里，IDE 内不需要再设一遍。最小可用配置如下：

model_provider = "spool"
model = "MODEL_ID"
disable_response_storage = true

[model_providers.spool]
name = "spool"
base_url = "https://rq.yunyc.work/v1"
wire_api = "responses"
env_key = "OPENAI_API_KEY"

把 MODEL_ID 换成你分组里的真实模型 id，可以用命令行确认一遍：

curl -s https://rq.yunyc.work/v1/models \
  -H "Authorization: Bearer $OPENAI_API_KEY"

key 从哪来

这是 IDE 场景最容易踩的一个坑：从程序坞、开始菜单或桌面图标启动的 IDE，读不到你在 ~/.zshrc 里 export 的环境变量，于是扩展会报鉴权失败，而同一台机器上命令行里的 codex 却一切正常。两个办法任选其一：

  • 写进 auth.json（推荐）：新建 ~/.codex/auth.json，内容只有一个字段。读不到环境变量时 Codex 会回落到这里，与 IDE 怎么启动无关。
  • 从终端启动 IDE：在项目目录里执行 code .（Cursor 用 cursor .，以此类推），这样启动的进程会继承当前终端的环境变量。
{
  "OPENAI_API_KEY": "sk-你的key"
}

改完 ~/.codex 下的任何文件，都要彻底退出 IDE 再打开，扩展才会重新加载配置。只关窗口不退进程通常不够。

IDE 里的设置项

扩展自身的设置（在设置界面搜 codex 可以看到）主要影响界面和执行审批行为，网关地址与 key 不在这里配。对话面板里可以选择模型和审批模式：模型下拉里出现的是 Codex 内置的候选项，若里面没有你要用的 id，就在 config.toml 的 model 字段里指定，以文件为准。

需要在 IDE 里用命令行版 Codex 时，直接在内置终端跑 codex 即可。内置终端会加载你的 shell 配置，环境变量正常可用。

验证

点开活动栏的 Codex 图标，发一条消息试试：

请回复你当前运行的模型名称

能正常回复就说明扩展已经在走 spool。

排查

  • 提示鉴权失败或 401：多半是扩展没读到 key。按上面的办法补一个 ~/.codex/auth.json，或从终端启动 IDE；同时确认 key 没有被换行、空格污染，必要时回 /keys 页面重新复制。
  • 404 并提示 not available for this group：模型不在当前分组的白名单里，换一个 /v1/models 返回的 id，确实需要就找管理员。
  • 其他 404：检查 base_url 是不是漏了 /v1，Codex 走 OpenAI 风格路径，这个后缀不能省。
  • 429 带 insufficient_quota：额度用完了，重试没有意义，找管理员。
  • 429 带 USER_RPM_EXCEEDED 或 GROUP_RPM_EXCEEDED：触发速率限制，稍等再试。
  • 403 带 INSUFFICIENT_BALANCE：余额不足，找管理员。
  • 503：暂时没有可用的上游账号，等一会儿重试。
  • 扩展一直转圈没有响应：先在终端跑一次 codex，如果命令行也不通，问题在配置文件而不是扩展。

Chatbox

Chatbox 是一款跨平台的 AI 聊天客户端，macOS、Windows、Linux、iOS、Android 都有版本。它同时内置了 Claude（Anthropic 协议）和 OpenAI 两种供应商类型，两种都能接 spool，桌面端和手机端的填写项完全一样。

开始之前

  1. 在控制台的 API Keys 页面创建一个密钥。创建时必须选择一个分组，分组决定这把密钥能看到哪些模型。
  2. 密钥创建后可以随时从列表里再次复制，不用担心当时没存下来。

下载安装

到 Chatbox 官网下载对应平台的安装包，装完直接启动即可，不需要额外依赖。

在哪里添加供应商

点击左下角的齿轮图标进入设置，切到「模型」（部分版本叫「模型提供方」）标签页。这里既可以直接使用内置的 Claude API / OpenAI API 类型，也可以新建一个自定义提供方。按你想用的模型族选一种即可。

方式 A：走 Anthropic 协议（Claude 系列模型）

模型提供方选择「Claude API」，然后填写：

字段填写内容
API Host / API 域名https://rq.yunyc.work
API Keysk-...（你在 /keys 创建的密钥）
模型你分组里可用的 Claude 模型 id

说明：Anthropic 协议的客户端会自己在域名后面拼 /v1/messages，所以这里的地址只填到域名，不要加 /v1。

方式 B：走 OpenAI 协议（GPT 及其他 OpenAI 兼容模型）

模型提供方选择「OpenAI API」，然后填写：

字段填写内容
API Host / API 域名https://rq.yunyc.work/v1
API Keysk-...（同一把密钥即可）
模型你分组里可用的模型 id

提示：两种方式用的是同一把密钥，不需要在控制台分别建两把。

怎么知道该填哪个模型

模型 id 由 spool 原样透传，能看到哪些取决于密钥所属的分组。在终端里问一次最准：

curl https://rq.yunyc.work/v1/models \
  -H "Authorization: Bearer sk-..."

返回列表里的 id 字段就是要填进 Chatbox 的名字，逐字复制，不要自己改大小写或连字符。

验证

保存设置后新建一个会话，发一条「你好」，能正常收到回复就说明接通了。

注意：最常见的坑是两种方式的地址差一个 /v1。OpenAI 方式漏掉 /v1，或者 Claude 方式多写了 /v1（请求会变成 /v1/v1/messages），都会得到 404 或者一直转圈。地址结尾也不要多加斜杠。

报错怎么看

  • 401：密钥不对，通常是粘贴时带了空格或换行，回 /keys 重新复制一次。
  • 404 且提示 not available for this group：模型不在你分组的白名单里，换一个 id 或找管理员。
  • 429 带 USER_RPM_EXCEEDED / GROUP_RPM_EXCEEDED：触发限速，等几秒再发。
  • 429 带 QUOTA_EXHAUSTED / USAGE_LIMIT_EXCEEDED：额度用完了，重试没有用，找管理员。

CC Switch

CC Switch 是一个跨平台桌面小工具，用来统一管理 Claude Code、Codex 等命令行工具的供应商配置。它的工作方式是直接替你改写 CLI 的配置文件，所以能做到一键在官方账号和 spool 之间来回切。

前置条件

CC Switch 管理的是 ~/.claude/ 和 ~/.codex/ 下的配置，所以至少要先装好其中一个 CLI，否则它没有可管理的对象。安装步骤见「Claude Code 配置」和「Codex 安装配置」两章。

下载安装

在官网或 GitHub Releases 页面下载对应系统的安装包。macOS 首次启动如果被系统拦截，去「系统设置 → 隐私与安全性」里放行一次。

添加 spool（Claude Code 标签页）

在顶部标签栏切到「Claude Code」，点「添加供应商」，填写：

字段填写内容
名称spool
ANTHROPIC_BASE_URLhttps://rq.yunyc.work
ANTHROPIC_AUTH_TOKENsk-...

说明：Claude Code 走 Anthropic 协议，地址不带 /v1。如果你的版本里字段名是 ANTHROPIC_API_KEY 也可以，spool 两个变量都认。

添加 spool（Codex 标签页）

切到「Codex」标签页，同样点「添加供应商」，填写：

字段填写内容
名称spool
base_urlhttps://rq.yunyc.work/v1
wire_apiresponses
model你分组里可用的模型 id
OPENAI_API_KEYsk-...

说明：Codex 走 OpenAI 协议，地址必须带 /v1。wire_api 决定请求打到 /responses 还是 /chat/completions，保持默认的 responses 即可。

模型 id 从哪来

curl https://rq.yunyc.work/v1/models \
  -H "Authorization: Bearer sk-..."

返回的是这把密钥所属分组能用的全部模型，id 原样透传，填进 CC Switch 时逐字复制。

切换与验证

在供应商列表里点一下 spool 就完成切换。CC Switch 会把值写进 ~/.claude/settings.json（Claude Code）或 ~/.codex/config.toml 与 ~/.codex/auth.json（Codex）。想确认写对了，可以直接看文件：

cat ~/.claude/settings.json
cat ~/.codex/config.toml

然后在终端各发一句话验证：

claude "你好"
codex "你好"

注意：切换只改文件，不会通知已经在运行的进程。如果 CLI 或 IDE 里的会话正开着，必须退出重开才会用上新配置——很多人以为切换没生效，其实是老进程还在用旧地址。

提示：CC Switch 是整体重写这两个配置文件的。如果你手工改过 settings.json 或 config.toml（比如自定义了 MCP、权限或代理），第一次用之前先备份一份。

Cherry Studio

Cherry Studio 是一款支持 Windows / macOS / Linux 的桌面 AI 客户端，可以自己配置模型服务商。它既支持 OpenAI 兼容协议，也支持 Anthropic 协议，两种都能接 spool。

下载安装

从官网下载对应平台的安装包，安装后启动应用。

在哪里添加服务商

点击左下角的齿轮图标进入设置，左侧菜单选「模型服务」（部分版本叫「模型提供商」）。在服务商列表底部点「添加」，先选类型，再填下面的字段。

类型选 OpenAI

字段填写内容
服务商类型OpenAI
服务商名称spool
API 密钥sk-...
API 地址https://rq.yunyc.work/v1

类型选 Anthropic

字段填写内容
服务商类型Anthropic
服务商名称spool
API 密钥sk-...
API 地址https://rq.yunyc.work

说明：同一把密钥两种类型都能用。区别只有一个：OpenAI 协议的地址带 /v1，Anthropic 协议的地址不带。

添加模型

Cherry Studio 不一定会自动拉全模型列表，需要手动添加模型 id。先拿到真实列表：

curl https://rq.yunyc.work/v1/models \
  -H "Authorization: Bearer sk-..."

然后在服务商详情页点「添加模型」，把返回结果里的 id 逐字填进去，需要几个就加几个。能看到哪些模型由密钥所属的分组决定。

启用并开始对话

在服务商详情面板右上角打开启用开关，回到对话界面，从顶部的模型下拉里选中刚添加的模型，发一条消息验证。

注意：Cherry Studio 会对你填的 API 地址做补全，这是最容易踩的地方。地址填到 /v1 就够了，它会自己接上 /chat/completions；如果你把完整路径都写进去，或者结尾多了一个斜杠，实际请求路径就会错，表现为 404 或者没有任何响应。填完后看一眼输入框下方显示的实际请求地址，确认它是 .../v1/chat/completions。

提示：如果地址没问题但某个模型返回 404 并提示 not available for this group，说明这个 id 不在你分组的白名单里，换一个或者找管理员。

Codex 桌面版（ChatGPT App）

ChatGPT 桌面客户端里内置了 Codex 智能体，并且支持直接用 API Key 登录，不必绑定 OpenAI 官方账号——这就是它能接 spool 的前提。它和 Codex CLI 共用 ~/.codex/ 下的配置。

下载安装

从官方下载页拿到对应系统的安装包，装好后启动。

用 API Key 登录

  1. 打开 App，点「登录」。
  2. 登录页不要点默认的那个 ChatGPT 账号登录按钮，选下方的「使用其他方式登录 / 使用 API Key」。
  3. 在弹出的 API 密钥输入框里粘贴你在 API Keys 页面创建的密钥（sk-...），确认继续。

把服务地址指向 spool

这一步是关键：只换密钥不换地址的话，请求仍然发往 OpenAI 官方。点左下角的设置图标可以查看当前配置，它对应的是 ~/.codex/config.toml。确认里面的服务地址是 spool，没有就直接改文件：

model_provider = "spool"
model = "填 /v1/models 里返回的模型 id"

[model_providers.spool]
name = "spool"
base_url = "https://rq.yunyc.work/v1"
wire_api = "responses"

密钥保存在 ~/.codex/auth.json（字段名 OPENAI_API_KEY），也可以用同名环境变量覆盖：

export OPENAI_BASE_URL=https://rq.yunyc.work/v1
export OPENAI_API_KEY=sk-...

改完配置文件后要重启 App 才会生效。

选模型

登录成功后在模型列表里选一个可用模型即可开始对话。可用范围由密钥所属分组决定，完整列表：

curl https://rq.yunyc.work/v1/models \
  -H "Authorization: Bearer sk-..."

注意：最常见的问题是登录成功了但地址还停在 OpenAI 官方（api.openai.com）。这时候请求根本没到 spool，表现为 401 或者提示账号无权限，而且在用量查询里也看不到任何记录。确认 base_url 是 https://rq.yunyc.work/v1，带 /v1、结尾不要多加斜杠。

说明：Codex 这条链路上额度耗尽会以 insufficient_quota 的形式返回（HTTP 429），含义等同于其他客户端看到的 QUOTA_EXHAUSTED。这种情况重试没有意义，找管理员。如果是密钥被删或过期，回 /keys 重新建一把再登录一次即可。

WorkBuddy

WorkBuddy 是腾讯 CodeBuddy 的桌面客户端，它提供了「自定义模型」入口，可以接入任意 OpenAI 兼容 API。把接口地址指向 spool，就能在里面用你分组下的模型。

安装并登录

  1. 从官网下载对应系统的安装包并安装。
  2. 启动客户端并登录自己的账号。自定义模型相关的设置项要登录之后才会出现。

在哪里添加自定义模型

  1. 点击对话框底部的模型选择器。
  2. 在弹出的模型列表最下方点「配置自定义模型」。
  3. 点「添加模型」，展开「提供商」下拉框，滚到最底部，在「其他」分组里选「自定义 / Custom」。

说明：这个弹窗只支持 OpenAI 兼容协议，没有 Anthropic 选项。所以接口地址要用带 /v1 的那种写法；Claude 系列模型同样可以通过这条 OpenAI 兼容链路调用。

填写字段

字段填写内容
提供商自定义 / Custom
接口地址https://rq.yunyc.work/v1
API Keysk-...（在 /keys 创建，可随时再次复制）
模型名称完整的模型 id

填好点保存。

模型名称怎么取

模型 id 由 spool 原样透传，以接口返回为准：

curl https://rq.yunyc.work/v1/models \
  -H "Authorization: Bearer sk-..."

WorkBuddy 里每个模型是一条独立配置，想用几个就按上面的步骤加几次。加完再打开底部的模型选择器，新模型就在列表里，选中即可对话。

提示：高级配置里建议勾上「工具调用」，否则模型没法使用工具。图片输入、思考模式这类开关要按你添加的这个模型是否真的支持来决定，模型不支持还勾上，请求会带上它不认识的参数而直接失败。

注意：模型没响应时，绝大多数情况是模型名称写错了。它必须和 /v1/models 返回的 id 逐字一致，大小写、连字符都不能差，写错会返回 404，并且提示 not available for this group（这条提示也可能意味着该模型确实不在你分组的白名单里）。其次检查接口地址是否带 /v1、结尾有没有多一个斜杠。

其他常见返回

  • 401：密钥错了或已被删除，回 /keys 重新复制或新建。
  • 403 带 INSUFFICIENT_BALANCE：余额不足，找管理员。
  • 429 带 USER_RPM_EXCEEDED / GROUP_RPM_EXCEEDED：限速，退避几秒重试。
  • 503：当前没有可用的上游账号，稍后再试。

令牌创建 & Token 获取

spool 的所有调用都靠一把 API 密钥做凭证：客户端把它放进请求头，网关据此认出是谁、属于哪个分组、能用哪些模型。本章从登录讲到把密钥填进客户端，正常两分钟就能走完。

前置：先有账号

spool 不开放自助注册，账号由管理员创建。没有账号就找管理员开一个，拿到之后打开 https://rq.yunyc.work/login 登录，登录后落在控制台 /dashboard。

创建一把密钥

  1. 进入 API Keys 页面：点顶部导航的「API Keys」，或直接访问 https://rq.yunyc.work/keys。
  2. 点击新建密钥。
  3. 选择分组（必选）。分组决定这把密钥能看到哪些模型，创建之后模型范围就按这个分组走。不确定该选哪个，问管理员。
  4. 填名称。写清用途和环境，例如 claude-code-mac、codex-local、ci-e2e。名称只给你自己看，但日后排查用量、吊销密钥全靠它认人。
  5. 按需填限制。页面上提供的额度上限、速率、有效期一类字段都是可选的，留空就跟随分组和账号的默认限制。给 CI 或临时脚本的密钥建议填一个额度上限，脚本跑飞了也有个兜底。
  6. 提交。列表里会出现这把密钥，点复制拿到完整 Token。

密钥随时可以再复制。spool 不是「只显示一次」的那种网关，任何时候回到 /keys 列表都能把完整密钥再复制一遍。所以不必抄进备忘录、便签或聊天记录，需要时回列表拿即可。

先验证再配置

拿到密钥后，先确认它能用、并且看清它在你的分组里能调哪些模型。模型清单以这个接口的返回为准，网关不改写模型 ID，返回什么 ID 就照原样传给客户端。

export SPOOL_KEY="替换成你刚复制的密钥"

curl -s https://rq.yunyc.work/v1/models \
  -H "Authorization: Bearer $SPOOL_KEY"

返回里的 data 数组就是这把密钥可用的全部模型。如果没有正常返回，对照下表：

返回含义怎么办
200密钥可用继续配置客户端
401密钥不对：抄漏了、前后带了空格、或者已经被删掉回 /keys 重新复制一遍
403 + INSUFFICIENT_BALANCE余额不足找管理员
404 + not available for this group这个模型不在你分组的白名单里换一个模型，或找管理员调整分组
429 + QUOTA_EXHAUSTED / USAGE_LIMIT_EXCEEDED额度用完了，重试没有用找管理员
429 + USER_RPM_EXCEEDED / GROUP_RPM_EXCEEDED触发限流退避几秒再重试
503当前没有可用的上游账号退避后重试，持续出现找管理员

配置进客户端

密钥用环境变量传给客户端就行。要注意的只有一点：Anthropic 系客户端用根地址，OpenAI 系客户端的地址末尾要带 /v1。

# Claude Code 等 Anthropic 系客户端：根地址，不带 /v1
export ANTHROPIC_BASE_URL="https://rq.yunyc.work"
export ANTHROPIC_AUTH_TOKEN="$SPOOL_KEY"

# Codex、OpenAI SDK 等 OpenAI 系客户端：带 /v1
export OPENAI_BASE_URL="https://rq.yunyc.work/v1"
export OPENAI_API_KEY="$SPOOL_KEY"

Claude Code 认 ANTHROPIC_AUTH_TOKEN，也认 ANTHROPIC_API_KEY，填哪个都可以，不用两个都填。各客户端的完整配置步骤见对应章节。

一个环境一把密钥

本地、CI、服务器分别建一把，名称里写清环境。这样做的好处很直接：用量能按密钥归因，出了问题知道是谁在跑；某一把需要吊销时，其他环境不受影响。每把密钥的用量在 /key-usage 页面按密钥查。

不要把密钥写进仓库

  • 密钥只放环境变量，或放本地不入库的配置文件（.env、~/.zshrc、CI 的 secret），不要硬编码在源码里。
  • 先把 .env 之类的文件写进 .gitignore，再往里写密钥。顺序反了就来不及了：提交之后再删除，密钥仍然留在 git 历史里。
  • 不要贴进群聊、工单、截图和日志；分享代码片段前把密钥换成占位符。

只要密钥可能已经外泄（提交进了仓库、贴进了群、打进了日志），就按已经泄露处理：去 /keys 把这把密钥删掉或禁用，新建一把替换，再把用到它的地方改过来。清理 git 历史是之后的事，先让泄露出去的那把失效。

gpt-image-2

gpt-image-2 是一个图像生成模型，通过 OpenAI 兼容的图像接口暴露。它不走 chat 接口，用的是 /v1/images/* 路径，所以调用方式和直连 OpenAI 官方图像接口一致，OpenAI SDK 改个 base_url 就能用。

能不能用取决于你的密钥所在分组。先请求 GET https://rq.yunyc.work/v1/models，返回的清单里有 gpt-image-2 才能调。如果调用返回 404 并提示 not available for this group，就是这个模型不在你分组的白名单里，换分组或找管理员。

接口地址

OpenAI 系接口，基址要带 /v1：

# 文生图
POST https://rq.yunyc.work/v1/images/generations

# 图像编辑 / 参考图
POST https://rq.yunyc.work/v1/images/edits

请求头带 Authorization: Bearer <你的密钥>。文生图用 application/json，上传图片时用 multipart/form-data。

文生图

curl -s https://rq.yunyc.work/v1/images/generations \
  -H "Authorization: Bearer $SPOOL_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2",
    "prompt": "A quiet workshop at dawn, warm light through dusty windows, photographic",
    "n": 1,
    "size": "1536x1024",
    "quality": "high",
    "output_format": "png"
  }' | jq -r '.data[0].b64_json' | base64 --decode > output.png
参数必填说明
model是固定传 gpt-image-2，模型 ID 由网关原样透传给上游
prompt是画面描述。主体、场景、光线、材质、构图、风格写得越具体越稳
n否出图张数，默认 1。张数越多越慢越贵
size否像素尺寸，形如 1024x1024、1536x1024、1024x1536，也可以传 auto
quality否auto / low / medium / high
output_format否png / jpeg / webp

参数集合以 OpenAI 图像接口为准，网关不做裁剪；这里只列最常用的几个。

返回

响应是 OpenAI 的 ImagesResponse。图片默认放在 data[0].b64_json 里，是 base64 编码的二进制，需要自己解码落盘（上面的 curl 用 jq 加 base64 做了这一步）。usage 是这次调用的 token 用量。

{
  "created": 1777347817,
  "data": [
    { "b64_json": "BASE64_IMAGE_DATA" }
  ],
  "usage": {
    "total_tokens": 772,
    "input_tokens": 212,
    "output_tokens": 560
  }
}

用 OpenAI SDK 调用

import base64, os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ["SPOOL_KEY"],
    base_url="https://rq.yunyc.work/v1",
)

resp = client.images.generate(
    model="gpt-image-2",
    prompt="A quiet workshop at dawn, warm light through dusty windows, photographic",
    n=1,
    size="1536x1024",
)

with open("output.png", "wb") as f:
    f.write(base64.b64decode(resp.data[0].b64_json))

图像编辑与参考图

/v1/images/edits 接受 multipart/form-data，把图片作为文件字段传上去，prompt 写编辑指令：说明保留什么、改什么。

curl -s https://rq.yunyc.work/v1/images/edits \
  -H "Authorization: Bearer $SPOOL_KEY" \
  -F "model=gpt-image-2" \
  -F "image[]=@input.png" \
  -F "prompt=把背景换成清晨的街道，保持主体和光线不变" \
  -F "size=1024x1024" \
  | jq -r '.data[0].b64_json' | base64 --decode > edited.png

SDK 里这个字段通常叫 image，可以传一个文件数组；curl 的 multipart 请求里用重复的 image[] 表单字段。

图像调用比文本调用更慢也更贵，尺寸越大、质量越高、参考图越多越明显。调 prompt 的阶段先用小尺寸和 quality: "low" 出草稿，方向定了再提到 medium 或 high 出终稿。
